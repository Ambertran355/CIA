Career Intelligence Assistant

Upload a job description and get a clear answer: is this opportunity worth pursuing for you, and what is the evidence?

The system has two parts. An AI agent reads the JD, compares it with your profile and returns the result as JSON. A Google Sheet acts as the repository: it takes the JSON, validates it again, and splits it into tables so you can track and compare opportunities over time.

From CV and JD to a result

Inside the agent, the two input sources pass through five stages before becoming one JSON block.

Inputs
[JD]

Job Description

A PDF uploaded in the current turn. Pasted text, links and images are not accepted.

[KB:CV]

Experience and achievements.

[KB:Evaluation]

Strengths and areas to develop.

[KB:CareerPath]

Preferred directions and directions to avoid.

Agent processing
  1. Check inputsIs it a PDF, is it actually a JD, does the profile have all three parts? If not, stop and report back.
  2. Understand the roleWhat problem the role solves, key responsibilities, success criteria, required and preferred skills.
  3. Match each requirementEach JD requirement goes into Strong Match, Transferable, Capability Gap or Missing Evidence, citing both the JD and your profile.
  4. Assess and recommendRate career alignment, skill fit, risk and learning opportunity; apply the fixed rule table D1–D8 to reach a recommendation.
  5. Self-validateCheck the structure and cross-field rules, fix any errors, then output.
Output
1 JSON blockFive data sections, each mapping to one table in the Sheet.

Every finding in the JSON carries a source label such as [JD] or [KB:CV]. No evidence, no conclusion.

How the JSON is split into the repository

Apps Script reads each section of the JSON block and writes it to its matching table. All rows for the same job are linked by one JOB ID.

{
  "job": {
    company, title,
    recommendation, decided_by
  },
  "jd_analysis": {
    role_summary, responsibilities,
    success_criteria, skills
  },
  "candidate_matching": [
    { requirement, priority,
      category, evidence }
    // one item per requirement
  ],
  "career_assessment": {
    alignment, skill_fit, risk,
    growth, learning, rationale
  },
  "company": {
    name, industry, notes
  }
}
JSON sectionSheet table
job→
01 Job Pipeline1 row per job: company, role, recommendation, ratings, application status.
jd_analysis→
02 JD Analysis1 row per job: role summary, responsibilities, success criteria, skills.
candidate_matching[]→
03 Candidate Matching1 row per requirement: match category, priority, evidence. One job can produce dozens of rows.
career_assessment→
04 Career Assessment1 row per job: rating for each dimension; reasons and evidence live in cell notes.
company→
05 Company Repository1 row per company: enriched over successive JDs without overwriting earlier information.

Re-validate

Apps Script reruns every rule. A single failure rejects the import and no rows are written.

Assign a JOB ID

Generates one unique ID and attaches it to every row of the job across all five tables.

Write all or nothing

If anything fails midway, the whole write is rolled back. No half-written jobs.

The agent checks before returning JSON, and Apps Script checks again before saving. With two independent gates, the repository only holds valid data.
